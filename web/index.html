Basics

Some applications hardcode SameSite=None on their session cookie even with no real cross-site need -- modern browsers' privacy/tracking-protection features can silently drop exactly that kind of cookie, breaking login with no clear error. Only enable this if you're seeing unexplained login/session failures with a specific upstream; a host that genuinely needs SameSite=None (an embeddable widget, a real cross-site OAuth flow) would break if this were on unconditionally.

When a connection presents a client certificate that chains to TrustBridge's root, forward its Subject CN in this header so the upstream app (if it's been set up to check for it) can trust it as an admin-login bypass. The header is always stripped from what a client sends directly, so this can never be spoofed by the request itself.

Serves a directory of files directly from disk instead of proxying to Upstream -- for a plain static site with no backend of its own. Takes priority over Upstream but not Redirect (Redirect above still wins if both are set). Path rewrite below is ignored on a static host.

Path rewrite (optional, advanced)

Rewrites the request path before it's sent to Upstream -- leave both blank unless you specifically need it. Pattern is a regular expression matched against the incoming path; replacement can use $1, $2, etc. for pattern's capture groups. Example: mount a GitLab project's wiki at a clean URL with pattern ^/((?:jpps|kb9gxk)/[^/]+)/?$ and replacement /$1/-/wikis/Home. Anchor the pattern to an explicit allowlist of the real value(s) it should match -- e.g. real namespace names, not just "two segments" -- or it can end up matching (and breaking) the target site's own assets/API calls or its own already-rewritten links.

Standalone DNS-01 certificates

Issue a certificate for a domain with no proxy host at all -- built for wildcards (*.example.com): issue it once here, then any host you create under that domain with ACME disabled just uses it automatically (no separate "attach" step -- TLS falls back from an exact-domain match to a covering wildcard cert). Tracked here so it's renewed automatically, same as a host's own cert. Issuing runs the real ACME flow (including a DNS propagation wait), so this can take up to a minute.

Access control lists

Reusable, named lists a host can select none, one, or several of (see the host form's "Access control" section). An IP allow list restricts by source IP/CIDR; a Login list gates behind a real sign-in page and can hold multiple username/password pairs; a Client cert list means a valid TrustBridge-issued client certificate satisfies this host's login gate (falling back to a selected Login list if none was presented) -- with zero subject entries, ANY valid cert qualifies; add entries via "Manage entries" to restrict it to specific certificates only.
